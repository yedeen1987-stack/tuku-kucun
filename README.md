# 拿货小程序

你在电脑上建拣货单，仓库工人在手机上按楼层拣货、点「已拿」，进度实时回到你这边。

跑在 Cloudflare 上，和「库存图记」同一套技术栈（Worker + D1 + R2），但独立部署、独立数据库，
不影响现在客户在用的图库。

## 为什么款号不用先登记

款号、色号、楼层、位置全部是**自由输入**，系统里没有款号主表。
新款随时进仓库，直接打上去就能用，不用先到哪里登记。

打过一次之后，这个款号就自动进了输入框的候选列表，下次打头几个字母就能选。
用得越久，录入越快。**这是特意这么设计的，不是偷懒。**

## 谁能看到什么

| | 你（管理员） | 工人 |
|---|---|---|
| 建单、改单、删条目 | ✅ | ❌ |
| 账号管理 | ✅ | ❌ |
| 看拣货单、点已拿 | ✅ | ✅ |
| 客户全名、价格 | 不进这个系统 | ❌ |

拣货单上只写**客户代号**（客户A、客户B），不要写客户全名——工人不需要知道。

实拍照片走 `/media/`，**必须登录才能看**。这一点和客户图库不同：图库的 `/media/` 是公开的，
这里不能公开，因为照片里有货架、堆放方式和库存量。

## 部署

需要一个 Cloudflare 账号。以下命令在项目目录里跑。

### 1. 装依赖

```
npm install
```

### 2. 建数据库和图片桶

```
npx wrangler d1 create textil134-picking
npx wrangler r2 bucket create textil134-picking-photos
```

第一条命令会输出一个 `database_id`，把它填进 `wrangler.jsonc`，替换掉那串全 0 的占位符。

### 3. 建表

```
npx wrangler d1 execute textil134-picking --remote --file=schema.sql
```

### 4. 设密钥

```
npx wrangler secret put SESSION_SECRET
```

要一串长随机字符串，可以这样生成：

```
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

`IMPORT_TOKEN` 是给以后本地识图系统推单用的，现在可以先不设（不设就等于关掉那个接口）。

### 5. 上线

```
npx wrangler deploy
```

部署完会给你一个网址。**第一次打开会自动进 `/setup` 让你建管理员账号；建完之后这个页面自动关闭。**

### 6. 建工人账号

用管理员登录 → 右上角「账号」→ 加工人账号。

把网址发给工人，让他们用手机浏览器打开后**「添加到主屏幕」**，这样就像个 App，而且能离线用。

## 本地调试

```
cp .env.example .dev.vars
npx wrangler d1 execute textil134-picking --local --file=schema.sql
npx wrangler dev
```

打开 http://localhost:8787

## 断网怎么办

仓库里信号差是常态，所以：

- 已经打开过的拣货单和照片会缓存下来，断网还能看
- 点「已拿」先改界面，操作排进手机本地队列
- 有信号了自动补发，右上角徽章显示队列情况（`online` / `3 na fila` / `enviando…`）
- 每条操作带一个唯一 id，**重发多少次都只记一次账**

## 「已拿」不等于扣库存

工人点「已拿」只表示**布已经从货架上拿下来了**，不代表卖掉了。

所以这个系统现在**完全不碰库存数量**。客户临时不要、换颜色、少拿一卷，都不会把库存数据搞乱。
等销售软件那边正式确认订单时，再做真正的库存扣减。

`picking_event` 是一张只追加的流水表，以后要接销售软件的 `stock_movement`，直接读它就行。

## 给以后本地系统留的接口

本地识图确认完款号和位置以后，可以直接推一整张拣货单过来：

```
PUT /api/import
Authorization: Bearer <IMPORT_TOKEN>

{
  "uuid": "本地生成的唯一id，用来防重复导入",
  "customer_label": "客户A",
  "items": [
    {"style": "YXS10237", "color": "3#", "qty": 2, "floor": "1楼", "spot": "左"}
  ]
}
```

同一个 `uuid` 重复推不会建出两张单，所以本地断网重试是安全的。

## 还没做的

- 照片目前原图存 R2，没做压缩和缩略图，量大了要加。
- 工人看到所有「已发出」的单，没有按人分配。
- 拣货单不和「库存图记」的款号做校验（这是故意的，见上面「为什么款号不用先登记」）。
