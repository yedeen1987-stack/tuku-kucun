# 先查一下实际数据量

我没法直接查你的数据库（D1 在你的 Cloudflare 账号里，销售软件的 SQLite 在你 Windows 机器上），
所以命令准备好了，你或 Codex 跑一下。

## 1. 销售软件那边：款号数、款号×色号组合数

在销售软件目录里：

```
python3 -c "
import sqlite3, pathlib
db = sqlite3.connect('data/stock.sqlite3')
print('款号数        ', db.execute('SELECT COUNT(DISTINCT style) FROM stock_code').fetchone()[0])
print('款号×色号组合 ', db.execute('SELECT COUNT(*) FROM stock_code').fetchone()[0])
print('装箱单批次    ', db.execute('SELECT COUNT(*) FROM stock_lot').fetchone()[0])
print('已设货位的款号', db.execute(\"SELECT COUNT(*) FROM stock_style WHERE location != ''\").fetchone()[0])
print()
print('--- location 实际填的什么（前20个）---')
for style, loc in db.execute(\"SELECT style,location FROM stock_style WHERE location != '' ORDER BY style LIMIT 20\"):
    print(' ', style, '->', repr(loc))
"
```

**第 2 行就是会推给图库的条目数**。旧版本超过 1000 就会被线上拒收；
打上这次的补丁之后没有上限了，但还是值得知道现在多少。

最后那段是为了回答「`stock_style.location` 现在填了没有、什么格式」——
这决定第 2 条的一次性迁移要不要做、怎么做。

## 2. 图库那边：线上现在有多少条库存记录

```
npx wrangler d1 execute textil134-stock-marker --remote --command "
  SELECT (SELECT COUNT(*) FROM stock_level) AS 库存记录,
         (SELECT COUNT(DISTINCT code) FROM product WHERE code != '') AS 图库款号,
         (SELECT COUNT(*) FROM style_location) AS 已设货位"
```

打完补丁以后，后台 **库存同步** 那一页也会直接显示这些数字和上次同步时间。

## 3. 如果销售软件的 location 已经有数据

按你定的第 2 条：**不建立两个可修改的货位源**，只做一次性对照迁移，
冲突列出来人工确认，不自动覆盖。

导出销售软件那一份，人工核对之后再用图库的「货位管理」批量录入：

```
python3 -c "
import sqlite3, csv, sys
db = sqlite3.connect('data/stock.sqlite3')
w = csv.writer(sys.stdout)
w.writerow(['款号','销售软件里的location'])
for row in db.execute(\"SELECT style,location FROM stock_style WHERE location != '' ORDER BY style\"):
    w.writerow(row)
" > 销售软件货位.csv
```

迁移完成后，销售软件那边的 `location` 就**不要再改了**——
图库的 `style_location` 是唯一真相源。
